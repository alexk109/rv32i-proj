# Formal proof harness (riscv-formal)

Bounded and k-inductive proofs that `cpu_core` retires instructions per the
RV32I spec, driven by [riscv-formal](https://github.com/YosysHQ/riscv-formal).

## Reproduce

From the repo root, with `yosys` (+ the `yosys-slang` plugin), `sby`, and
`yices` available (see `tools/setup.sh`):

```sh
make formal-setup      # one-time: build/fetch yosys-slang, yices, sby into tools/
make formal-gen        # stage this dir into riscv-formal and generate the checks
make formal-run        # race the checks; ~80s on 8 cores
make formal-status     # PASS/FAIL/UNKNOWN counts and any counterexamples
```

`make formal-run FORMAL_MODE=prove` switches BMC to unbounded k-induction;
`make formal-gen FORMAL_CFG=deep` regenerates at ~2x depth (see `deep.cfg`).

`make formal-setup` clones [riscv-formal](https://github.com/YosysHQ/riscv-formal)
into `tools/riscv-formal` at a pinned commit (see `RISCV_FORMAL_REF` in
`tools/setup.sh`); it is not committed here. The pin is deliberate — the check
set and the invariants below are written against that exact revision of
`insns/` and `checks/`, so a moving upstream would silently change what the
passing counts mean.

`genchecks.py` derives the core name from its working directory, so it only runs
from inside `<riscv-formal>/cores/<name>/`. `make formal-gen` therefore creates
`tools/riscv-formal/cores/cpu_pipeline/` and stages `checks.cfg` and `wrapper.sv`
into it. That directory is generated, never hand-edited.

## What's here

| File | Role |
|------|------|
| `wrapper.sv` | riscv-formal top: instantiates `cpu_core`, exposes RVFI, and supplies the free-variable memory. Read by yosys's native frontend (owns the `rvformal_rand_reg` free variables the slang frontend ignores). |
| `mem_responder.sv` | Stands in for instr/data memory on the core's buses: fetched word and load word are unconstrained, so the instruction and load checks stay non-vacuous. |
| `invariants.sv` | Strengthening invariants (`bind` into `cpu_core` and `reg_file`) that k-induction needs — x0-reads-zero at each stage, retirement-order monotonicity. |
| `checks.cfg` / `deep.cfg` | Check set + solver/depth config consumed by `genchecks.py`. |
| `engines.py` / `status.py` | Rewrite generated `.sby` files to race engines; summarize results. |

## How the core stays clean

`cpu_core` carries no verification logic. The RVFI retirement interface is
generated by `verif/rvfi_monitor.sv`, `bind`-attached to the core via
`verif/rvfi_bind.sv` (shared with simulation), and its memories are external —
so the same core synthesizes with no formal scaffolding compiled in.
